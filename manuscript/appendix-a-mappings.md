# 付録A — 相互参照表

本付録は、本文が背景に保持しているトレーサビリティを担う。その目的は、保証チェーンを双方向にたどれるようにすることである。ある脅威から、それに対処したことを証明するテストへと下る方向にも、失敗したテストから、それが未対処のまま残す脅威へと遡る方向にもたどれる。コントロール欄や要件欄が空であれば、それは未対処の脅威、あるいは要件に落とし込まれていないコントロールを意味する。実在するギャップであり、まさにこの表が存在する理由である。検証欄は性質が異なる。この欄には第10章で定義された*書籍内*テストを列挙しており、これは代表的な一部にすぎない。要件からテストへの網羅的なマトリクスは、コンパニオンキットのカバレッジチェック（REQ-054）が維持・強制する生きた成果物である。したがって、ここでVT欄が薄いことはキットへのポインタであって、未検証のコントロールの告白ではない。

この表について5点補足する。第一に、ランタイムポスチャ要件（REQ-040..REQ-047）とロギング要件（REQ-030）は、特定の1行に属するのではなく、多くの脅威行に繰り返し現れる。これらは横断的な要件だからである。ポスチャの縮退と再構成可能なロギングは一般的なケースに対処し、個別のコントロールを補強する。第二に、出典マッピングのレジスタは、TH-10に対して要件仕様に存在しない要件識別子（REQ-016）を割り当てていた。本書ではこれを、TH-10の濫用経路を実際に担うインシデント対応・濫用ブロッキング要件である REQ-035 として扱う。この置き換えは出典側の仕様に対して検証済みである。出典のマッピングレジスタは現在 TH-10 の行に REQ-035 を持ち、存在しない識別子は出典側から削除された。本書の扱いと出典は一致しており、変更履歴はこの項目を解決済みとして記録している。第三に、TH-04の検証欄には、書籍内のテスト識別子ではなく、テストの*手法*を記している。メモリ可逆性（REQ-022）とロールバックの実証（REQ-034）は動的テストと証跡によって証明されるものであり、第10章の代表的な表はこれらの個別テストを列挙していない。それらはキットのマスターマトリクスに収載されている。この欄は、無関係な静的識別子を借用する代わりに、どの種類のテストが適用されるか、そして網羅的な一覧がどこにあるかを示している。第四に、2026-07-31 改訂で追加した証跡の完全性に関する要件（REQ-055、REQ-056、REQ-057）は、TH-09 の行にまとめて現れると同時に、それぞれが守る証跡の持ち主である脅威の行にも個別に現れる。いずれも、成果物が存在することだけを求めていた要件と対をなすからである。REQ-055 は REQ-030 と、REQ-056 は REQ-015 と、REQ-057 は REQ-033 と対になる。対になった行を読むとは、その両側を読むということである。すなわち、成果物と、それを信じるに足る理由の両方を読むということである。第五に、2026-08-01 改訂で追加した保証の独立性に関する要件（REQ-058、REQ-059、REQ-060、REQ-061）は、その対の1つ上の層に位置する。これらが問うのは、成果物が真実かどうかではなく、それを主張した主体に主張する資格があったのか、採点の基準となった一覧が外部から来たのか、そして黙って省くことが許されていなかったか、である。したがって REQ-058 は TH-09 とガバナンス側の TH-10 の両方に、REQ-061 はサプライチェーンの TH-07 に、REQ-059 と REQ-060 は報告層そのものが敵手となる TH-09 に現れる。
